# Friends

Date: 2026-11-24. Status: built. Quick access to the accounts you share with.

## Decisions (validated with the user)

- **One-way list**, like contacts: you add an account of this instance by exact username; no
  request, no acceptance, and the other person is not told. Removing is silent too.
- **Suggestions**: accounts you shared something with, or that shared something with you, not yet
  friends. Most recent first, at most 20.
- Disabled accounts are hidden from the list and suggestions; deleted ones leave it (cascade).
- **Share dialog / sheet**: friends who do not have access yet show as one-tap picks that share
  with the chosen permission. Typing a username still works.
- Clients: API, web (Friends page in the account menu and on the Shared page), phone (share sheet
  picks, Friends screen from Shared, LS-DO).

## Model and API

- `friends(user_id, friend_id, created_at)`, PK `(user_id, friend_id)`, both FKs to `users`
  `ON DELETE CASCADE`, `CHECK (user_id <> friend_id)`, index on `friend_id`. At most 500 per user.
- `GET /api/friends` → `{ friends: FriendDto[] (by display name), suggestions: MemberDto[] }`.
- `POST /api/friends { username }` → 201 `FriendDto`, idempotent; 422 no such account or yourself.
- `DELETE /api/friends/{username}` → 204, 404 if not a friend.
- Session or phone token (data routes).

## Risks

- Account probing: adding reveals whether a username exists, as sharing already does. No new leak.
