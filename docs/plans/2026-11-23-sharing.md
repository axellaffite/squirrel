# Sharing and comments

Date: 2026-11-23. Status: built. Lifts "cross-user sharing" from the v1 out-of-scope list.

## Decisions (validated with the user)

- Share a **folder, a file (a photo is a file) or an album** with **accounts on this instance**,
  picked by exact username, as **read** or **write**. No public links. Web only.
- **Write on a folder**: create folders, upload, rename, move inside the shared folder, trash.
  Everything added belongs to the **folder owner** and counts against **their quota**; trashed items
  go to the owner's trash. The shared folder itself can only be renamed, moved or trashed by its owner.
- **Write on an album**: add your own photos, remove the ones you added. The owner can remove any.
  Rename, cover and deletion stay with the owner. When a write share is revoked, that person's photos
  leave the album.
- **Comments**: one flat thread per shared folder, file or album, for everyone who can see it
  (owner included). Authors edit or delete theirs; the owner can delete any on their items.
  A deleted account's comments stay, shown as "Deleted user".
- Shared photos do **not** enter the recipient's timeline, search, people or duplicates: they are
  reached from "Shared with me". Owner-only data (faces, people names) is never shown to others.

## Model

- `shares(id, owner_id, recipient_id, node_id | album_id, permission read|write, created_at)`,
  composite FKs to `(node_id, owner_id)` / `(album_id, owner_id)` cascading, one share per
  (subject, recipient), never to oneself.
- `comments(id, owner_id, node_id | album_id, author_id NULL on account deletion, body 1–4000,
  created_at, edited_at)`, same composite FKs (deleting the subject deletes its thread).
- `album_items.added_by` (the photo's owner), FK `(node_id, added_by)` → `assets`, replacing the
  same-owner FK; backfilled with `owner_id`.
- `upload_sessions.created_by` (the uploader): sessions are found by `(id, created_by)`, written to
  `owner_id`'s tree.
- **One resolver** `access::node(user, id) → (node, Owner | Write | Read)`: owner, else the
  strongest live share on the node or an ancestor, else Read through an album the user owns or is
  shared. Routes that serve or change a node call it instead of `find_live(owner_id, …)`.
  No access is exactly 404 (as today).

## Risks

- Authorization regressions: every changed route gets a cross-user test (stranger 404, reader
  cannot write, writer cannot escape the subtree, revoked share is 404 at once).
- Dedup probe leaking the owner's library: in a shared folder, an upload is linked without bytes
  only when the hash is in the **uploader's** own library.
- Moves out of a shared folder: source and destination must be inside the same write share (or owned).
